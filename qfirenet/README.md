# QFireNet — AI-Powered Digital Trust & Cyber Risk Assessment Platform

> **"Know Before You Trust."**

QFireNet is a full-stack cybersecurity platform that lets users submit a **website URL**, **raw email text**, or **Android APK file** and receive a single explainable **Trust Score (0–100)** with a risk level (Low / Medium / High), per-signal breakdown, and a plain-language AI explanation generated by **Groq (Llama 3.3 70B)**.

## Quick Start

### Option A: Docker Compose (Recommended — one command)

**Prerequisites:** Docker + Docker Compose installed.

```bash
# 1. Clone the repo and enter the project directory
cd qfirenet/

# 2. Create the backend .env file
cp backend/.env.example backend/.env
# Edit backend/.env and fill in:
#   GROQ_API_KEY=gsk_your_key_here
#   JWT_SECRET_KEY=your_random_32_char_secret

# 3. Start the full stack
docker-compose up --build

# Access points:
#   Frontend:  http://localhost
#   Backend:   http://localhost:8000
#   API Docs:  http://localhost:8000/docs
```

## API Reference

All endpoints are documented interactively at `http://localhost:8000/docs`.

### Authentication

```http
POST /auth/register
Content-Type: application/json

{ "email": "user@example.com", "password": "securepass123" }

→ { "access_token": "eyJ...", "token_type": "bearer", "user": {...} }
```

```http
POST /auth/login
{ "email": "user@example.com", "password": "securepass123" }
```

### Scan Endpoints

All scan endpoints work anonymously or authenticated. Include the JWT in the `Authorization: Bearer <token>` header to save scans to your history.

**Website scan:**
```http
POST /scan/website
{ "url": "https://example.com" }
```

**Email scan:**
```http
POST /scan/email
{
  "raw_headers": "Received: from ...\nAuthentication-Results: mx.google.com;\n  spf=pass ...",
  "body": "Dear user, act now to verify your account..."
}
```

**APK scan:**
```http
POST /scan/apk
Content-Type: multipart/form-data
file: <binary APK data>
```

**All scans return:**
```json
{
  "trust_score": 73.5,
  "risk_level": "Low",
  "breakdown": { "Signal Name": 85.0, ... },
  "explanation": "AI-generated plain English explanation...",
  "scanned_at": "2025-01-01T12:00:00Z"
}
```

**Scan history (requires auth):**
```http
GET /history?page=1&page_size=20
Authorization: Bearer <token>
```

## Scoring Logic

### Website Trust Score
| Signal                | Weight | Rationale |
|---|---|---|
| Phishing Heuristics   | 35%    | URL patterns are the most reliable phishing indicator |
| SSL Certificate       | 25%    | Invalid/expired cert = hard failure |
| Domain Age (WHOIS)    | 25%    | Newly registered domains are high-risk |
| PQC Readiness         | 15%    | Informational / forward-looking; soft bonus |

### Email Trust Score
| Signal                     | Weight |
|---|---|
| Header Auth (SPF/DKIM/DMARC) | 40% |
| Content Heuristics           | 60% |

### APK Trust Score
| Signal                | Weight |
|---|---|
| Permission Risk Score | 75%    |
| App Metadata Score    | 25%    |

**Risk Levels:** ≥70 = Low | 40–69 = Medium | <40 = High

## Technology Choices Explained

| Technology | Why chosen |
|---|---|
| **FastAPI** | Auto-generates OpenAPI docs; async support; Python type hints = self-documenting code |
| **Groq + Llama 3.3 70B** | Ultra-fast inference; free tier; strong reasoning for security explanations |
| **androguard** | Most mature Python library for static APK analysis |
| **python-jose** | Lightweight JWT library that follows RFC 7519 exactly |
| **passlib + bcrypt** | Industry standard; bcrypt is deliberately slow to resist brute force |
| **React + Tailwind** | Component reusability; utility-first CSS for rapid dark-theme iteration |
| **PostgreSQL** | JSON column type for raw_results; production-grade; ACID compliant |

## Post-Quantum Cryptography (PQC) — Honest Implementation

The "quantum" angle is implemented **honestly**:

- We inspect the TLS cipher suite negotiated by the server during the SSL handshake.
- We look for **Kyber, ML-KEM, or X25519Kyber** indicators — NIST-standardised PQC algorithms.
- **Most sites will fail this check** — that is expected and correct. PQC adoption is still early-stage globally (2024–2025).
- The PQC signal carries **only 15% weight** and provides a soft bonus for ready sites rather than a hard penalty for classical-only sites.
- We do **not** simulate quantum computing or claim to perform actual quantum operations.

## Limitations (MVP Scope)

- Email scan uses **pasted headers only** — no live inbox integration.
- APK scan is **static analysis only** — no dynamic execution sandbox.
- JWT stored in **localStorage** — httpOnly cookies are more secure for production.
- PQC detection depends on whether the TLS handshake exposes cipher info — some servers may not.
